# ScriptStack 用户使用手册

版本：3.0.2  
适用客户端：macOS Apple Silicon、macOS Intel、Windows x64  
当前 Beta 默认服务器：`http://49.235.153.151`

## 1. ScriptStack 是什么

ScriptStack 是一套“桌面客户端 + 云端生产后端”的剧本生产系统。

用户日常打开的是本机桌面 App，不是浏览器网页。桌面 App 负责界面、文件选择、本地导入入口、用户交互；服务器负责账号、数据库、剧本生产流程、LLM 调用、导入材料管理、长篇项目数据、资产处理等重活。

可以把它理解成：

```text
你的电脑上的 ScriptStack App
    |
    | HTTP/HTTPS API
    v
ScriptStack 云端服务器
    |
    | 数据库 / LLM / 文件材料 / 项目流程
    v
剧本、长篇项目、角色场景道具资产、提示词结果
```

当前 `544834.xyz` 域名在外网访问时会被服务商拦截到 DNSPod webblock，因此本轮 Beta 暂时使用 `http://49.235.153.151` 作为网页和桌面客户端的 API 入口。域名备案/解除拦截后，再切回正式 HTTPS 域名。

## 2. 支持的平台

### macOS

支持两类 Mac：

- Apple Silicon：M1、M2、M3、M4 及后续 M 系列芯片。
- Intel Mac：较老的英特尔芯片 Mac。

推荐发布一个 Universal macOS 安装包。Universal 包会同时包含 Apple Silicon 与 Intel 两套二进制，用户不需要自己判断芯片类型。

### Windows

支持 Windows x64：

- Windows 10 及以上。
- Windows 11。
- Intel / AMD 64 位电脑。

Windows 安装包通过 GitHub Actions 的 Windows runner 打包，不建议在 Mac 上强行交叉打包 Windows 安装器。

## 3. 安装客户端

### macOS 安装

1. 获取 `ScriptStack_3.0.2_universal.dmg` 或类似名称的 DMG 文件。
2. 双击打开 DMG。
3. 将 `ScriptStack.app` 拖入 `Applications`。
4. 从启动台或应用程序文件夹打开 ScriptStack。

如果 macOS 提示“无法验证开发者”：

1. 打开“系统设置”。
2. 进入“隐私与安全性”。
3. 找到 ScriptStack 的拦截提示。
4. 点击“仍要打开”。

正式对外发布时，建议配置 Apple Developer ID 签名与 notarization，减少这类提示。

### Windows 安装

1. 从 GitHub Actions 或 Release 页面下载 Windows 安装包。
2. 优先使用 `.msi` 或 `.exe` 安装器。
3. 双击安装。
4. 从开始菜单打开 ScriptStack。

如果 Windows SmartScreen 提示风险：

1. 点击“更多信息”。
2. 点击“仍要运行”。

正式对外发布时，建议配置代码签名证书。

## 4. 第一次打开

第一次打开后，App 会连接默认服务器：

```text
http://49.235.153.151
```

如果服务器可用，界面会正常进入登录页或主界面。

如果出现“底层通信断裂”“无法访问 API”“登录失败但密码确定正确”等问题，先看本手册第 14 节“常见故障”。

## 5. 登录与账号

ScriptStack 使用服务器账号体系。账号数据保存在服务器数据库里，不保存在用户本机。

### 登录

1. 打开 ScriptStack。
2. 输入用户名。
3. 输入密码。
4. 点击登录。

登录后，App 会在当前会话里保存访问 token。退出登录、token 失效或重新安装后，系统会尽量清理旧登录态，避免卸载重装后仍然自动登录。

### 退出登录

1. 点击左下角个人中心。
2. 点击退出登录。
3. App 会清空本机保存的登录状态。

### 管理员账号

管理员账号由服务器 `.env` 中的配置生成或更新。不要在聊天、文档、截图里暴露管理员密码。

## 6. 主界面结构

ScriptStack 的主界面围绕几个核心入口：

- 灵感枢纽：从概念、导入剧本、导入长篇材料开始项目。
- 项目库：查看、恢复、重命名、删除已有项目。
- 剧本任务：查看已有剧本生成任务和导入剧本。
- 视觉资产：管理角色、场景、道具等资产。
- 提示词工坊：生成图像和视频提示词。
- 设置：配置模型接口、连接测试、系统信息。

左侧图标栏用于快速切换模块。顶部或页面内按钮用于创建项目、导入材料、启动推演。

## 7. 推荐工作方式

### 单集短剧

适合已有一个明确短剧想法，目标是快速生成一集。

流程：

1. 进入灵感枢纽。
2. 输入核心概念。
3. 设置时长、题材、短片模式等参数。
4. 点击开始推演。
5. 进入 8 步剧本工作流。
6. 按步骤生成、检查、修改。
7. 最终定稿后进入资产提取或提示词生成。

### 导入已有剧本

适合用户已经有一份完整单集剧本。

流程：

1. 进入灵感枢纽或剧本任务页。
2. 选择导入已有剧本。
3. 使用文件导入或粘贴文本。
4. 系统将剧本保存为任务。
5. 后续可以进入分镜、资产提取、提示词生成。

### 长篇/连续剧

适合小说改剧本、连续短剧、长篇故事逐集生产。

流程：

1. 创建 Series Root，也就是整部剧的大项目。
2. 导入小说、大纲、章节、人物设定等 Source Material。
3. 对长文本进行粗切。
4. 用户确认 Source Chunks。
5. 选择一个或多个 Source Chunks 创建 Episode。
6. 每集独立走剧本流程。
7. 每集完成后生成 Story State Snapshot。
8. 下一集读取上一集快照，保持人物、道具、冲突、结尾状态连续。

重点原则：

- 小说章节不等于剧集集数。
- Source Chunk 是素材片段。
- Episode 是生产单元。
- 长篇不要一次性生成全部内容。
- 不要求用户一开始输入总集数。

## 8. 8 步剧本工作流

每个剧本项目会进入结构化工作流。具体步骤以当前界面为准，但核心逻辑是从概念逐步生长成完整剧本。

常见步骤包括：

1. 核心概念：确认故事卖点、主矛盾、目标用户。
2. 结构规划：建立开端、发展、高潮、反转、结尾。
3. 角色设定：生成主角、配角、关系、动机。
4. 场景大纲：拆成可拍摄的场景。
5. 剧本初稿：形成正式剧本文字。
6. 分镜规划：生成镜头和视觉表达方向。
7. 视觉风格：统一影像质感。
8. 最终定稿：汇总成可继续生产的版本。

每一步都应该做到：

- 先看生成结果。
- 不满意就修改或重新生成。
- 满意再进入下一步。
- 关键节点保存版本。

## 9. 文件导入

ScriptStack 支持文本材料导入。根据当前实现，目标格式包括：

- TXT
- Markdown
- DOCX
- PDF 文字层

扫描版 PDF 第一版不做 OCR。如果 PDF 是图片扫描件，系统可能无法提取正文。

### 导入材料类型

导入后，系统会尽量识别材料类型：

- 成品剧本
- 小说或长篇原材料
- 大纲
- 人物设定
- 混合材料

不同材料进入不同流程：

- 成品剧本可以直接创建剧本任务。
- 小说和大文本进入 Source Material / Source Chunk 流程。
- 大纲用于项目规划。
- 人物设定先保存为材料，后续可转资产。
- 混合材料需要用户确认分类。

### 中文 TXT 乱码

系统后端会尝试识别 UTF-8、GBK、GB18030。若仍出现乱码：

1. 用文本编辑器打开原文件。
2. 另存为 UTF-8。
3. 重新导入。

## 10. 长篇项目

长篇项目不是“把时长拉长”的单集项目，而是一个项目树。

核心对象：

- Series Root：整部剧项目。
- Episode：具体一集。
- Source Material：用户导入的原始材料。
- Source Chunk：从材料切出来的片段。
- Story State Snapshot：每集完成后的剧情记忆快照。

### 有小说或大文本

推荐流程：

1. 导入小说或长篇文本。
2. 系统按章节标题、自然段、空行、字数阈值给出粗切建议。
3. 用户在切片面板里确认、合并、拆分。
4. 保存 Source Chunks。
5. 选择片段改编成某一集。
6. 每集完成后生成记忆快照。

不要完全交给模型自动决定最终切分。长篇切分会影响戏剧节奏，最终决定权应该在用户。

### 没有小说，从零创作长篇

推荐流程：

1. 用户只输入核心概念。
2. 系统生成第一集 Pilot。
3. 第一集完成后，系统生成 2-3 个下一集方向。
4. 用户选择方向，或手写调整。
5. 系统读取上一集 Story State Snapshot。
6. 继续生成下一集。
7. 直到用户选择终结本剧。

这样不会强迫用户一开始决定总集数，也避免一次性生成过长内容导致质量失真。

## 11. 资产提取与道具合板

剧本完成后，可以提取：

- 角色
- 场景
- 道具

道具数量很多时，推荐使用资产合板：

1. 系统根据道具数量生成网格计划。
2. 每个格子绑定一个道具 ID。
3. 生成一张规则合板图。
4. 后端按格子裁切。
5. 裁切出的子图绑定回对应道具。

系统不需要再用多模态模型重新识别每个格子是什么，因为生成前已经知道 Cell A1、A2、A3 分别对应哪个道具。

第一版建议使用规则网格：

- 2x2：适合 4 个道具。
- 3x3：适合 9 个道具。
- 4x4：适合 16 个道具。
- 18 个道具可拆成两张 3x3。

## 12. 设置模型接口

进入设置页后，可以配置文本模型和图像模型。

常见字段：

- Endpoint：模型接口地址。
- API Key：访问密钥。
- Model：模型名。
- Mode：OpenAI 兼容或自定义。

配置后应点击连接测试。

如果测试失败：

- 检查 Endpoint 是否带 `/v1`。
- 检查 API Key 是否有效。
- 检查模型名是否正确。
- 检查服务器是否能访问该模型供应商。

## 13. 服务器与客户端发布

### 服务器

服务器上运行：

- `/opt/scriptstack/scriptstack-server`
- `systemd` 服务：`scriptstack`
- Nginx HTTPS 反代
- SQLite 数据库
- 上传文件目录

常用状态检查：

```bash
systemctl status scriptstack
systemctl status nginx
```

### macOS 客户端

推荐打 Universal 包：

```bash
npm run tauri:build:remote:mac-universal
```

产物位置：

```text
target/release/bundle/dmg/
target/release/bundle/macos/
```

### Windows 客户端

Windows 包在 GitHub Actions 中打：

1. 打开 GitHub 仓库。
2. 进入 Actions。
3. 选择 `Desktop Release Packages`。
4. 点击 `Run workflow`。
5. 当前 Beta 确认 `api_base` 是 `http://49.235.153.151`；域名恢复后再改回正式 HTTPS 域名。
6. 等待 Windows x64 job 完成。
7. 从 Artifacts 下载 `ScriptStack-Windows-x64`。

产物通常包括：

- `.msi`
- `.exe`

## 14. 常见故障

### 打开浏览器显示 ERR_CONNECTION_CLOSED

先确认你是不是在用浏览器访问。ScriptStack 的主要使用方式是桌面 App。

如果浏览器也需要访问，用于测试服务器时：

1. 当前先访问 `http://49.235.153.151`。
2. 检查域名 A 记录是否指向服务器 IPv4。
3. 检查是否存在错误 AAAA 记录。
4. 检查代理或浏览器 DNS 是否劫持。
5. 检查 Nginx 是否正常。
6. 检查域名是否被服务商拦截或要求备案。

当前 `544834.xyz` 公共 DNS 解析本身可以指向服务器，但外网 HTTP 会被跳转到 DNSPod webblock，HTTPS 会被直接断开。这不是 ScriptStack 后端崩溃，而是域名访问层被拦截；临时方案是使用 `http://49.235.153.151`。

### App 提示底层通信断裂

可能原因：

- 服务器不可达。
- token 过期。
- 未登录。
- API 地址没有编进客户端。
- 本地网络代理拦截 HTTPS。

处理方式：

1. 退出登录后重新登录。
2. 检查服务器是否可访问。
3. 确认客户端是用 `tauri:build:remote` 系列命令打包。
4. 如果是开发模式，使用 `npm run tauri:dev:remote`。

### 登录失败

检查：

- 用户名是否正确。
- 密码是否正确。
- 服务器 `.env` 是否配置了管理员账号。
- 服务是否重启过，管理员账号是否已写入数据库。

### 导入文件没有弹出文件选择器

文件选择器必须在桌面 App 中使用。浏览器页面没有 Tauri 原生能力，不能完整模拟本机文件选择。

处理方式：

1. 确认打开的是 `ScriptStack.app` 或 Windows 桌面安装版。
2. 不要只在浏览器里测试文件导入。
3. 如果仍无反应，检查 Tauri dialog 插件是否启用。

### Windows 无法安装

可能原因：

- 安装包未签名，被 SmartScreen 拦截。
- 系统版本太旧。
- WebView2 Runtime 缺失。

处理方式：

1. Windows 10/11 通常自带 WebView2。
2. 若缺失，安装 Microsoft Edge WebView2 Runtime。
3. 如果 SmartScreen 拦截，点击“更多信息”后继续运行。

### macOS 无法打开

可能原因：

- 未签名或未 notarize。
- 下载文件被 Gatekeeper 标记。

处理方式：

1. 系统设置 → 隐私与安全性 → 仍要打开。
2. 正式发布时使用 Apple Developer ID 签名。

## 15. 推荐验收清单

发布一个新版本前，至少检查：

- macOS Universal DMG 能在 M 系列 Mac 打开。
- macOS Universal DMG 能在 Intel Mac 打开。
- Windows x64 安装包能在 Windows 10/11 安装。
- App 登录服务器成功。
- 项目库能加载。
- 新建剧本项目成功。
- 8 步工作流至少能生成第一步。
- 文件导入能弹出原生文件选择器。
- 导入 TXT 不乱码。
- 导入 DOCX 能提取正文。
- 长篇材料能创建 Source Material。
- 道具合板计划能生成。
- 退出登录后无法访问受保护 API。

## 16. 一句话原则

用户使用桌面 App；服务器跑数据和生产流程；Windows 包交给 GitHub Actions 打；macOS 发 Universal 包；不要把浏览器预览当成最终产品形态。
